# HuntX Repository Audit & Remediation — 2026-07-26

Branch: `claude/repo-audit-optimization-2y7erg` · Base: `main@4da38fa`

This document records a full audit pass over the HuntX codebase and the
concrete, behavior-preserving remediations applied in this branch. Every change
described here is committed and verified: **288 tests pass**, the CI-gated lint
selection is clean, and `mypy` reports no issues across all 75 source files.

The guiding principle for remediation was *fix what is provably correct and
low-risk; document what carries behavior risk*. Findings that would change
runtime semantics of the ingestion/publish pipeline in ways a maintainer should
sign off on are listed in [Section 4](#4-known-risks-documented-not-changed)
rather than silently altered.

### Top-line findings

1. **CI was red on `main`.** Commit `4da38fa` loosened config validation to
   silently swallow (a) missing required env vars → empty string and (b) invalid
   `api_id` → `None`, breaking two tests that the `pytest --strict-config` gate
   runs. **Fixed** — see §3.1.
2. **`RejectsStore` wrote to the wrong directory** after `paths.set_paths()`
   because it bound its base path at import time. **Fixed** — §3.2.
3. **`RawStore.get`/`exists` built filesystem paths from an unvalidated hash.**
   **Fixed** (hex validation) — §3.2.
4. **Hardened publish stage could abort the whole run** on a single malformed
   build result where the base class degrades gracefully. **Fixed** — §3.3.
5. **Published dev outputs were written non-atomically** while the manifest was
   atomic. **Fixed** — §3.3.

## 2. Module-by-module audit

### `config/`
- `env_expand.py`: `${VAR}` (unset, no default) silently expanded to `""`,
  masking misconfiguration. `config.prod.yaml` uses bare `${TELEGRAM_API_ID}`
  etc., so a production deploy missing those vars would proceed with empty
  credentials. **Fixed** to fail loud; `${VAR:-default}` remains the sanctioned
  optional/dev escape hatch.
- `schema.py`: `validate_api_id` swallowed non-numeric input (e.g. a typo or an
  unexpanded `${...}`) as `None`. **Fixed** to raise on genuine garbage while
  still treating absent/empty/zero as an optional `None`.
- `validate.py`: sound layered validation with a `HUNTX_STRICT`/`CI` gate for
  credential strictness. No change needed.

### `store/` and `state/`
- `rejects.py`: import-time default-argument path binding. **Fixed** to resolve
  `paths.REJECTS_DIR` at runtime, matching `RawStore`/`ArtifactStore`.
- `raw_store.py`: `get`/`exists` now reject any value that is not a 64-char
  lowercase hex digest before path construction. **Fixed.**
- `artifact_store.py`: already performs `resolve()` + `is_relative_to` traversal
  defense — verified clean.
- `state/repo.py`, `state/ingestion_queue.py`: SQL is consistently parameterized;
  f-strings only interpolate `?`-placeholder counts / validated ints. `db.py`
  closes connections in `finally`. Verified clean.

### `core/`
- `hardened_orchestrator.py`: unguarded `build_result["route_name"]` subscript in
  the publish loop. **Fixed** to skip non-dict results and use `.get`, matching
  the base `Orchestrator`.
- `orchestrator.py`: three published dev-output files written with plain
  `write_text` while the manifest used `atomic_write`. **Fixed** to use
  `atomic_write` for all four.
- `hardened_orchestrator.py` thread-pool shutdown, `session_lease.py` TOCTOU,
  deprecated `get_event_loop()` usage: documented in §4.

### `connectors/`
- `base.py` / `telegram_user/connector.py`: sync wrappers use deprecated
  `asyncio.get_event_loop()` + `run_until_complete` without an `is_running`
  check; `__del__` triggers network cleanup during GC. Documented in §4.
- Download size caps rely on self-reported `file_size` metadata before an
  uncapped `response.read()`. Documented in §4.

### `formats/`
- Decoders wrap malformed-input parsing in broad `except` returning `[]`/`None`
  — intentional and safe against crashes. Embedded decryption keys/passwords in
  `common/crypto.py` are format constants for decoding known third-party proxy
  formats (with env overrides), not application secrets. Documented in §4.

## 3. Applied remediations (verified)

### 3.1 Config validation — deterministic failure restored
- `config/env_expand.py`: a bare `${VAR}` that is unset now raises
  `ValueError("Missing required environment variable: VAR")`. `${VAR:-default}`
  (including empty `${VAR:-}`) still resolves to the default.
- `config/schema.py`: `validate_api_id` raises on non-empty non-numeric input;
  absent/empty/zero still map to `None`.
- New tests: `tests/test_env_expand.py` (9 cases), `tests/test_schema_validators.py`
  (9 cases). The two previously-failing `test_config_loader.py` cases now pass.

### 3.2 Store hardening
- `store/rejects.py`: base directory resolved at runtime.
- `store/raw_store.py`: `_is_valid_sha256` gate on `get`/`exists`.
- New tests: `tests/test_store_hardening.py` (runtime-reconfiguration + traversal
  rejection + hash-validation cases).

### 3.3 Orchestrator hardening
- `core/hardened_orchestrator.py`: defensive skip of malformed build results.
- `core/orchestrator.py`: atomic writes for `proxies.txt`, `proxies_b64sub.txt`,
  `proxies.json`.

### 3.4 Lint / hygiene
- Removed 31 unused imports (`autoflake`), 1 dead local, 3 placeholder-less
  f-strings, 1 lambda-assignment. Stripped trailing whitespace / normalized
  final newlines across 39 files. Flake8 findings dropped from ~350 to ~128
  (remainder is non-gated style: long lines, blank-line spacing).
- Untracked `temp_state.db` (a mutating SQLite runtime artifact regenerated by
  the test suite) and extended `.gitignore` to cover `*.db` and test scratch dirs.

## 4. Known risks (documented, not changed)

These are real findings whose fixes would change pipeline runtime semantics or
depend on maintainer intent. They are left for review rather than altered
autonomously.

1. **Hardened thread-pool shutdown** (`hardened_orchestrator.py`): `shutdown(wait=False, cancel_futures=True)` does not stop already-running build/publish threads, so `timed_out`/`completed` status can be reported while publish threads keep delivering. Fixing correctly requires cooperative cancellation in the pipelines.
2. ~~Deprecated event-loop usage in `connectors/base.py`~~ **Remediated in follow-up commit**: `AsyncSyncIterator.__iter__` now uses `asyncio.run` (fresh loop) and falls back to a dedicated worker thread when a loop is already running on the calling thread — no more `get_event_loop()`/re-entrancy crash (`tests/test_connector_base_iter.py`). The remaining `get_event_loop()` sites in `telegram_user/connector.py` sync wrappers and orchestrator entry points still warrant a coordinated migration.
3. **`__del__`-based connector cleanup** (`telegram_user/connector.py`): relocate to the existing async context-manager path; GC-time network I/O is unreliable.
4. ~~Download size caps rely on self-reported `file_size` before an uncapped read~~ **Remediated in follow-up commit**: the Bot API downloader now performs a bounded `read(MAX_DOWNLOAD_BYTES + 1)` and discards over-cap bodies (`tests/test_download_cap.py`); both Telethon paths (`telegram_user/connector.py`, `windowed.py`) enforce the 25 MB cap on actual downloaded bytes after `download_media` in addition to the metadata pre-check.
5. **`session_lease.py` staleness check** is TOCTOU-racy — two runs can both reclaim the same lease, weakening the exclusive-session guarantee.
6. ~~`opaque_bundle.build` buffers all route blobs with no aggregate cap~~ **Remediated in follow-up commit**: bundle assembly is now bounded by `HUNTX_OPAQUE_BUNDLE_MAX_BYTES` (default 1 GiB) and `HUNTX_OPAQUE_BUNDLE_MAX_ENTRIES` (default 100 000); truncation is logged loudly, never silent (`tests/test_opaque_bundle_bounds.py`).
7. **Embedded format keys/passwords** in `common/crypto.py` and **AES-ECB / low-iteration PBKDF2**: inherent to decoding the third-party formats HuntX targets; documented as accepted, format-dictated constants (env-overridable) rather than secrets to rotate.
8. **Repo weight**: `data_archive/` (~800 MB), `outputs_dev/` (~123 MB), `outputs/` (~32 MB) are tracked runtime artifacts. Consider moving to Releases/LFS and untracking — left untouched here because deleting ~1 GB of tracked data is a maintainer decision.
9. **`pyaes` build** fails under modern setuptools; the pinned `pyaes==1.6.1` sdist needs `setuptools<60` to build a wheel. Consider a maintained fork or a constraint note in the dev setup.
