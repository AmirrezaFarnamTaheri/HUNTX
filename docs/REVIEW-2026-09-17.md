## Remaining work and review limits

No live ingestion, Telegram publication, S3 persistence, fleet deployment, third-party probe execution or GitHub Actions dispatch was performed. Docker and Helm were not available on the shell PATH. Hosted vulnerability checks and dependency security certification were not performed. This work does not prove all supported protocols produce valid configurations in every client.

A follow-up pass on the same day repaired the frontend defects raised earlier, each reproduced first in Node and then re-verified:

- `safeAtob` treated `atob`'s one-character-per-byte output as text, so non-ASCII Base64 payloads (Cyrillic, CJK, emoji names) rendered as Latin-1 mojibake. It now converts to bytes and decodes UTF-8 via `TextDecoder`, with the legacy escape fallback retained. Verified with a VMess node named `Тегеран σταν 東京`.
- Shadowsocks passwords containing colons were truncated at the first colon because the method/password split discarded everything after it. Parsing now splits on the first colon only, matching the Python backend. Verified with `aes-256-gcm:pass:word:123` and with an empty password in both userinfo and whole-URI forms.
- VLESS `flow` parameters (for example `xtls-rprx-vision`) were never parsed, so generated Sing-box outbounds omitted the field. The decoder now carries `flow` through to `nodeToSingboxOutbound`.
- VLESS and Trojan query paths were decoded twice: `URLSearchParams` already percent-decodes values and the code called `decodeURIComponent` again, corrupting paths containing literal `%` sequences. The query value is now used as decoded, which matches the backend's single `parse_qsl` decode.
- An integrity-verified release with `entries: []` was treated as missing data and replaced by the bundled demo proxies. A verified empty release is now authoritative; the checksum-valid empty artifact was confirmed in Chromium (status pill "Artifact integrity verified", endpoint count 0, no bundled nodes).
- Bundled fallback was one-shot: once live data had been shown, a later failed load left demo data on screen permanently. Fallback is now re-applied on every unavailable cycle (the dynamic `import` cache makes this cheap), and a failed live load restores the bundled snapshot instead of leaving stale live records.

New regressions: six focused Node tests in `tests/frontend_runtime.test.mjs` (UTF-8, colon passwords, flow, single query decode, empty release, fallback transition) and two browser tests in `tests/frontend_browser.spec.mjs` (checksum-valid empty release end to end; inspector preserving names, credentials, flow and encoded paths). Current counts: 16 Node runtime tests, 11 browser tests, Python 841 passed / 1 skipped, Go tests/vet/build, flake8 and mypy all pass on the final tree.

One independent review subagent was dispatched for the Python publication paths; it stalled before producing findings and was stopped, so its areas retain only the owner's tests plus this pass's earlier verification.

Still open from inspection, not repaired: `buildSingboxConfig` in `docs/assets/js/decoder.js` emits route and DNS rules referencing `dns-out` and rule sets (`geosite-cn`, `geoip-cn`, `geosite-category-ads-all`) that the generated config never declares, so clients must provide them separately or reject the config. Changing it needs a reproduction in a real client first.

Existing documentation also contains stale bundle-generation descriptions: the checked frontend validator reports native-module delivery and an absent legacy bundle. Broader documentation cleanup remains outside this patch.

Review attention covered state retention and provenance, checkpoint/persistence handoff, administrative generation verification, bot startup and CLI defaults, selected connector/configuration/format paths, and frontend delivery. Other areas received baseline tests or inspection only. Remaining candidates need focused reproductions before repairs, not a claim that the application is perfected.
